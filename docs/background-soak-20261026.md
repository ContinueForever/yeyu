# 可选后台磁盘六小时稳定性实验：2026-10-26

本轮已完成六阶段、360 个 60 秒计时窗口，共 21,600 秒计时，墙钟 22,368.445 秒（约 6 小时 12 分 48 秒）。12,836,802 次已发请求中 12,836,802 次成功、0 次失败；另有 123,198 / 12,960,000 个计划时刻未发（0.9506%）。六次阶段整组重启核对均通过，原服务保护记录相同，临时实验服务已停止。

该结果验收的是可选 `--disk-executor background` 路径在本次负载下的稳定性。[此前 18 轮新旧对照](cloud-peer-disk-20261026.md)的大状态 P99.9 仍为旧值 51.82%，未达到预设减半门槛；`performance_gate=false`，默认继续同步。长实验启动前已明确变更验收目的，保存初始选择、失败门槛和变更记录；本次通过不能改写性能结论。

正式活动为 2026-10-26 12:06:28 至 2026-10-26 18:19:16（Asia/Shanghai）。计时不含预载、预热、阶段恢复和收尾；墙钟包括这些工作。此前两个两秒预检窗口另有 2,400 次成功、零失败／未发和两次恢复，不并入正式结果。

## 配置和统计口径

- 云端核心与十一项执行工具冻结为 `834bb43`，新程序 SHA-256 为 `e58f9fe7…f43ff85b7`。GCC 13.3、RelWithDebInfo、云端构建关闭测试；`4193bb0` 只修正旧测试，生产源码逐文件一致，启动前 push／PR CI 均通过。
- 磁盘执行固定 background；KV 快照编码器按 sync／background 轮换，冷 value 净负载 1／8／15 MiB，每阶段独立目录和 60 个窗口。journal、ReadIndex、adaptive、128 条／1 MiB 快照触发、4 MiB journal 检查点。关闭追踪且不创建追踪记录器。
- 固定 Leader 2，32 连接、600 offered rps、128 B 热值、每窗口预热一秒，按窗口轮换 0／50／90% 写，每组合 20 个窗口。每连接最多一个未完成请求，忙时跳过的计划时刻单列。
- 仍使用现有三台双逻辑 CPU ECS，原服务并行运行，发压共置 Follower 3；实验节点和发压服务各限一个 CPU／512 MiB。600 rps 是输入计划，不是独立机器测得的服务容量。
- 下表是同一连续阶段中相关窗口的统计量中位数。P99／P99.9 不是把全部请求合并后的分位数，也不把相邻窗口当作独立重复。计划延迟从计划时刻算到返回；请求延迟从实际发送算到返回。

## 恢复、保护与独立核验

六阶段结束后分别仅停止实验节点，再以同一程序／配置重开，在线检查该阶段所有冷值、最后窗口原始序列重建的 256 个热值、锚值和 revision。恢复状态记录的键数、索引、同任期与模式由离线再次核对。冻结工具实际读取并比较全部值，但恢复文件只保留计数、锚值 revision 和状态，没有逐个保存读到的 value 哈希；公开证据不能离线重建每一次恢复响应字节，不将其称为逐值哈希证明。

原服务 512 个旧实验键、四个保护值的集合哈希、2852 个键与 applied index 711089 前后相同；原 PID、程序 SHA-256、未重启状态和亲和性核对一致。终态收集后只清理本 tag 临时服务，三机原服务继续运行。

当前仓库核验器解包数据后逐请求重算实际延迟、计划日历、未发时刻、读写比例、最终热值及汇总，并核对真实启动参数、程序哈希、无追踪状态、资源计数、任期、队列守恒、阶段恢复、原服务保护和清理。七项语义负例直接修改真实预检数据，分别验证错误模式、队列计数、日历、分位数、CPU 计数、恢复 revision 和追踪状态仍被拒绝；不是只验证文件哈希。

[公开归档](../benchmarks/published/background-soak-20261026/README.md)保留全部客户 gzip 原字节，外层归档按 70 MiB 分块，诊断地址／主机名／路径一致脱敏并列出前后哈希。构建源码、执行工具、下载清单和原始／派生数据分开保存；只执行当前仓库核验工具，不运行归档工具来自证。私钥、token、控制配置、业务值、原数据库和程序均不公开。
