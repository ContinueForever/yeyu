# yewukv 六个月工程路线图

更新：2026-10-24。目标是交付可复现、可质询的 C++ 分布式系统作品，而不是在简历上罗列尚未验证的组件。本文是当前计划。

## 当前基线

代码已有单机 Reactor/RPC/WAL 基线，并新增完整的固定三 voter 节点状态机、真实磁盘 Raft 存储、节点间 TCP/RPC、复制进度、当前任期多数派提交及有序 KV 应用。业务读默认经 ReadIndex 本轮多数派确认并等待应用位置；旧 Leader 隔离后不能直接读取本地 map 返回成功。本机三进程版本已经后台部署，完成 Leader 强杀、全节点重启、双向隔离、日志追赶、并发历史模型校验，以及完整普通／sanitizer 回归。还有可校验的停机备份／恢复和三轮重复的批处理 A/B 基准；详见[集群说明](cluster.md)。

已知边界：原单机 KV WAL 与新的 Raft 日志彼此独立。逻辑 Raft 持久状态上限 64 MiB，默认增量追加 journal 并发布原子代次检查点；最多 32 个就绪写命令共享一次同步持久化，默认 GET 不再占用日志。KV/Raft 原子快照、日志前缀回收与分块 InstallSnapshot 已通过本机容量、全节点重启及 ENOSPC/EIO 注入验收。三台 ECS 的[基础演练](cloud-acceptance-20261023.md)、[45 轮性能基线](cloud-performance-20261024.md)和新增[18 轮真实混合故障](engineering-next-20261024.md)已有公开证据。真实断电与多日负载尚待补充；三台虚拟机也不能直接视为三个已核实的独立故障域。

## 定位与取舍

2026-10-24 的读路径／RPC／调度关联累计 48 轮、5,024,663 次纯读，数值证据已公开。在固定机器、32 连接热读负载下，Leader 全线程固定 CPU 0 后吞吐中位数约 +32%、P99 从 43.225 降至 7.617 ms；仍有 87.525 ms 单次尾部，默认配置已恢复，详见[调度报告](cloud-scheduling-20261024.md)。这是环境相关的部署调优，不据此宣称算法提速。

本轮进一步交付 [C++ 后台快照编码、容量／过载与 CAS](engineering-next-20261024.md)：普通／ASan 各 143 项通过，状态机／快照组件 TSan 13 项通过；42 轮正式负载、637,823 个已发请求。8 MiB 冷 value＋固定快照压力下吞吐中位数 +40.46%、P99 −34.88%，同时保留 299.259 ms 最坏请求、同步发布暂停和额外所有权开销。版本条件更新已有真实旧目录升级、并发发布与恢复验证，Watch 尚未实现。只有三台机器，下一步继续补独立发压、默认策略下长稳态和剩余同步暂停。

主线是固定三节点、单 Raft Group 的小型元数据 KV 服务。第一版保证 Put/Get/Delete 和明确的强一致语义，提供可复现的故障与性能报告。所有量化结果都须注明硬件、版本、负载、样本和失败情形。

在三节点正确性与恢复验收之前，不开展 Multi-Raft、在线分片、成员变更、自研 SkipList/SSTable、Redis 兼容层或 io_uring。若求职岗位转向数据库内核，再单独评估 LSM 路线；不在主线中同时推进两套复杂系统。

## 里程碑与验收门槛

| 阶段 | 建议时间 | 交付物 | 放行标准 |
| --- | --- | --- | --- |
| G0 可复现单机基线 | 第 1–2 周 | 整理 Git 提交与 README；单节点持久化 Compose；接入 WAL 后的基准 | 干净检出可构建、CI 通过；容器重启后能读取成功写入；基准保留命令、原始样本与环境信息 |
| G1 可控 Raft 核心 | 第 3–6 周 | 与网络解耦的状态机、持久化接口和确定性消息／时钟模拟器 | 覆盖 term/vote、候选人日志新旧判断、日志冲突、当前任期提交规则、旧 Leader 回归；固定随机种子可复现失败 |
| G2 固定三节点服务 | 第 7–12 周 | term/vote/log 持久化、节点间 RPC、复制与多数派提交、线性一致读、客户端重定向 | 已确认写入在 Leader 强杀和单节点重启后仍可读取；少数派不能确认写入；读不返回旧 Leader 的过期值 |
| G3 鲁棒性 | 第 13–16 周 | 故障编排与操作历史记录、简化模型校验、恢复报告 | 分区、延迟、重启、消息重排与重复请求可重复运行；违反模型时保存种子和请求历史，修复后加入回归 |
| G4 可用性 | 第 17–20 周 | 三节点持久化部署、指标、容量与备份恢复策略、最小元数据使用案例 | 另一台机器按文档可启动、写入、故障演练、备份恢复；资源耗尽行为和已知限制写明 |
| G5 性能与作品交付 | 第 21–24 周 | 独立负载发生器、P50/P95/P99 与吞吐报告、瓶颈分析、设计复盘、简历材料 | 固定负载重复测量；区分客户端与服务端瓶颈；报告一项实测优化及其代价；演示和故障实验可复现 |

阶段按验收门槛推进，不因到了某周就宣称完成。若 G2 到第 12 周仍未满足安全性验收，停止增加功能：先把单机持久 KV 做到可复现、可运行、可解释，再决定是否继续共识层。

## 当前验收进度

1. G0：单机基线保留，原网络与 WAL 回归继续通过。
2. G1：节点核心、真实持久化和逻辑时钟／消息模拟器已经接通，100 个固定种子、每个 1000 步可重放故障序列，包含快照与重启。
3. G2：固定三节点服务、默认 ReadIndex 和可选日志读路径已实现，通过本机真实进程故障测试；新增显式 IPv4 监听和[系统级云部署工具](cloud-deployment.md)。历史三机各 126 项普通测试及基础演练已有归档；最新追加六类故障各三轮的混合负载与少数派保护，有限范围见[本轮报告](engineering-next-20261024.md)。
4. G3：已有代理隔离、SIGKILL、重启、乱序／重复消息及有界逐 key 历史校验；同机延长活动见 [2026-10-22 报告](local-followup-20261022.md)。新增真实三机 18 轮、2,491 个模型操作，保留 48 个未知写入，并检查跨轮持久值、快照追赶及整组恢复；仍待多日与真实断电验证。
5. G4：已有本机用户服务、状态／磁盘指标和 SHA-256 备份恢复；本机 I/O 故障、容量、队列及慢连接验收通过，三机系统级部署已有记录。配置应用新增 revision／CAS、并发冲突、ABA 及旧快照迁移；云端小队列探测得到 1,016 BUSY／8 OK 且恢复正常，云端备份恢复和更广真实资源耗尽仍待补充。
6. G5：已有批处理、持久化、读调度和 fixed/adaptive 的重复对照；历史 72 轮同机与 45 轮三机基线分别归档。新增 48 轮读路径／调度证据公开、C++ 快照编码对照、27 轮闭环与 9 轮计划到达负载，报告吞吐、P99／P99.9、最大值、CPU／RSS 及 148,257 个未发计划时刻。仍未达到独立发压机、多日稳态与生产容量门槛。

早期容量／快照验收见[本机报告](local-acceptance-20261021.md)，journal、ReadIndex 与配置应用见[第一轮优化](local-optimization-20261021.md)，读调度、自适应检查点及恢复对照见[后续优化](local-followup-20261022.md)。各历史测试数属于当时版本，不能叠加成当前回归数。最新入口为[三机工程报告](engineering-next-20261024.md)，后续重点是同步发布剩余暂停、独立发压与长稳态、更广 CAS 故障交错，以及独立人员按公开材料复现。保持现有强一致读写与恢复契约，不以增加技术名词替代验收。

当前 G0 核对（2026-09-26）：本地完整测试及基准完成。实际 Docker 构建发现本机 `build/` 污染构建上下文，现用 `.dockerignore` 排除。单节点 Compose 镜像已成功构建，健康检查通过；RPC 写入返回 `OK`，容器重启后、以及 `docker compose down` 后重新创建容器时，均从保留的 `node-data` 卷读取到原值。[GitHub Actions 首轮运行](https://github.com/ContinueForever/yeyu/actions/runs/36230842263)的普通构建、ASan/UBSan 构建、测试、格式检查和容器重建后的 WAL 恢复检查全部通过。公开 CI 分支现包含两次本机基准的命令、报告与原始样本；源码压缩包因包含无关文档未公开。G0 的代码、持久恢复和 CI 门槛已通过；合并 PR 后仍应从另一台机器验证文档与基准复现。

求职准备与工程主线并行：从现在开始投递和复盘；每周保留算法编码、操作系统／网络／数据库基础与系统设计练习。项目验收不能替代现场编码能力。
