# yewukv 六个月工程路线图

更新：2026-09-25。目标是交付可复现、可质询的 C++ 分布式系统作品，而不是在简历上罗列尚未验证的组件。本文是当前计划。

## 当前基线

代码已有 Reactor、文本协议、Protobuf RPC 客户端与服务端、有界单线程存储执行器、带 CRC 的同步 WAL、重启回放及日志回收。普通 CTest 55 项通过；WAL 的 8 项与 Raft 选举／日志规则测试在 ASan/UBSan 下通过。已有 WAL 前和 WAL 后的本机 RPC 开发基准；包含本机环境信息的报告与原始样本保留在本地。Raft 仅有网络外的选举和日志规则内核，Compose 当前仅部署单节点；没有三副本或线性一致读写的证据。

已知边界：每次写入单独 `fdatasync`；一个存储工作线程串行执行；map 无总内存配额；WAL 默认上限 1 GiB，回收要复制存活数据；没有磁盘满、真实断电、长时间负载或跨机器验收。当前 WAL 是已应用状态机的本地日志，**不是**可直接复用的 Raft term/index 日志。

## 定位与取舍

主线是固定三节点、单 Raft Group 的小型元数据 KV 服务。第一版保证 Put/Get/Delete 和明确的强一致语义，提供可复现的故障与性能报告。所有量化结果都须注明硬件、版本、负载、样本和失败情形。

在三节点正确性与恢复验收之前，不开展 Multi-Raft、在线分片、成员变更、自研 SkipList/SSTable、Redis 兼容层或 io_uring。若求职岗位转向数据库内核，再单独评估 LSM 路线；不在主线中同时推进两套复杂系统。

## 里程碑与验收门槛

| 阶段 | 建议时间 | 交付物 | 放行标准 |
| --- | --- | --- | --- |
| G0 可复现单机基线 | 第 1–2 周 | 整理 Git 提交与 README；单节点持久化 Compose；接入 WAL 后的基准 | 干净检出可构建、CI 通过；容器重启后能读取成功写入；基准保留命令、原始样本与环境信息 |
| G1 可控 Raft 核心 | 第 3–6 周 | 与网络解耦的状态机、持久化接口和确定性消息／时钟模拟器 | 覆盖 term/vote、候选人日志新旧判断、日志冲突、当前任期提交规则、旧 Leader 回归；固定随机种子可复现失败 |
| G2 固定三节点服务 | 第 7–12 周 | term/vote/log 持久化、节点间 RPC、复制与多数派提交、线性一致读、客户端重定向 | 已确认写入在 Leader 强杀和单节点重启后仍可读取；少数派不能确认写入；读不返回旧 Leader 的过期值 |
| G3 鲁棒性 | 第 13–16 周 | 故障编排与操作历史记录、简化模型校验、恢复报告 | 分区、延迟、重启、消息重排与重复请求可重复运行；违反模型时保存种子和请求历史，修复后加入回归 |
| G4 可用性 | 第 17–20 周 | 三节点持久化部署、指标、容量与备份恢复策略、最小元数据使用案例 | 另一台机器按文档可启动、写入、故障演练、备份恢复；资源耗尽行为和已知限制写明 |
| G5 性能与作品交付 | 第 21–24 周 | 独立负载发生器、P50/P95/P99 与吞吐报告、瓶颈分析、设计复盘、简历材料 | 固定负载重复测量；区分客户端与服务端瓶颈；报告一项实测优化及其代价；演示和故障实验可复现 |

阶段按验收门槛推进，不因到了某周就宣称完成。若 G2 到第 12 周仍未满足安全性验收，停止增加功能：先把单机持久 KV 做到可复现、可运行、可解释，再决定是否继续共识层。

## 本轮执行顺序

1. 修正仓库对当前阶段的表述，单节点部署必须有持久卷，不能把独立容器称为集群。
2. 固化 G0 的构建、测试和基准证据；把历史结果与当前 WAL 结果分开标注。
3. 为 G1 先写明状态机事件、输出、持久化时序及确定性测试边界，再实现最小选举与复制内核。

G1 的选举和日志规则内核已有确定性测试，契约见[Raft 核心契约](raft-contract.md)；持久化 Raft 日志、节点集成、传输和服务端接线尚未完成。

当前 G0 核对（2026-09-26）：本地完整测试及基准完成。实际 Docker 构建发现本机 `build/` 污染构建上下文，现用 `.dockerignore` 排除。单节点 Compose 镜像已成功构建，健康检查通过；RPC 写入返回 `OK`，容器重启后、以及 `docker compose down` 后重新创建容器时，均从保留的 `node-data` 卷读取到原值。新增的 CI 冒烟脚本在本机通过，并接入 GitHub Actions。公开 CI 分支只包含源码、测试、部署与设计文档；托管 runner 的运行结果仍待观察，G0 的 CI 放行项仍未完成。

求职准备与工程主线并行：从现在开始投递和复盘；每周保留算法编码、操作系统／网络／数据库基础与系统设计练习。项目验收不能替代现场编码能力。
