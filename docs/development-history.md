## yewukv 六个月工程路线图

更新：2026-10-26。目标是交付可复现、可质询的 C++ 分布式系统作品，而不是在简历上罗列尚未验证的组件。本文是当前计划。

### 当前基线

代码已有单机 Reactor/RPC/WAL 基线，并新增完整的固定三 voter 节点状态机、真实磁盘 Raft 存储、节点间 TCP/RPC、复制进度、当前任期多数派提交及有序 KV 应用。业务读默认经 ReadIndex 本轮多数派确认并等待应用位置；旧 Leader 隔离后不能直接读取本地 map 返回成功。本机三进程版本已经后台部署，完成 Leader 强杀、全节点重启、双向隔离、日志追赶、并发历史模型校验，以及完整普通／sanitizer 回归。还有可校验的停机备份／恢复和三轮重复的批处理 A/B 基准；详见[集群说明](cluster.md)。

已知边界：原单机 KV WAL 与新的 Raft 日志彼此独立。逻辑 Raft 持久状态上限 64 MiB，默认增量追加 journal 并发布原子代次检查点；最多 32 个就绪写命令共享一次同步持久化，默认 GET 不再占用日志。KV/Raft 原子快照、日志前缀回收与分块 InstallSnapshot 已通过本机容量、全节点重启及 ENOSPC/EIO 注入验收。三台 ECS 的[基础演练](cloud-acceptance-20261023.md)、[45 轮性能基线](cloud-performance-20261024.md)和新增[18 轮真实混合故障](engineering-next-20261024.md)已有公开证据。真实断电与多日负载尚待补充；三台虚拟机也不能直接视为三个已核实的独立故障域。

### 定位与取舍

2026-10-24 的读路径／RPC／调度关联累计 48 轮、5,024,663 次纯读，数值证据已公开。在固定机器、32 连接热读负载下，Leader 全线程固定 CPU 0 后吞吐中位数约 +32%、P99 从 43.225 降至 7.617 ms；仍有 87.525 ms 单次尾部，默认配置已恢复，详见[调度报告](cloud-scheduling-20261024.md)。这是环境相关的部署调优，不据此宣称算法提速。

本轮进一步交付 [C++ 后台快照编码、容量／过载与 CAS](engineering-next-20261024.md)：普通／ASan 各 143 项通过，状态机／快照组件 TSan 13 项通过；42 轮正式负载、637,823 个已发请求。8 MiB 冷 value＋固定快照压力下吞吐中位数 +40.46%、P99 −34.88%，同时保留 299.259 ms 最坏请求、同步发布暂停和额外所有权开销。版本条件更新已有真实旧目录升级、并发发布与恢复验证，Watch 尚未实现。

后续短任务完成持久化分阶段指标、CAS 故障历史与 C++ 发压器，普通／ASan 各 148 项通过；到达日历修正另做专项回归。[六小时默认策略窗口](cloud-soak-20261024.md)已完成：360 个一分钟窗口、12,872,548 次已发请求成功，87,452 个未发计划时刻，六次整组重启检查通过。每配置只有一个约一小时相位，且客户端共置；最长请求 520.703 ms，后台快照发布仍有 391.430 ms 暂停。后续单次持久化时间关联已完成下述短时观测；下一步验证有序后台磁盘发布，独立发压、重复长对照、多日运行和真实断电仍待补充。

主线是固定三节点、单 Raft Group 的小型元数据 KV 服务。第一版保证 Put/Get/Delete 和明确的强一致语义，提供可复现的故障与性能报告。所有量化结果都须注明硬件、版本、负载、样本和失败情形。
