# 本机 journal / ReadIndex 优化证据

对应[优化报告](../../../docs/local-optimization-20261021.md)。全部运行在同一台机器，不能据此宣称跨主机容灾或生产吞吐。

- `performance/`：同一二进制的 image/log、journal/log、journal/ReadIndex 三模式交错对照；四种负载各三轮，每轮 10 秒，共 36 轮、1,265,078 次计时操作。包含每请求延迟／完成时间、逐秒趋势、CPU/RSS、持久化阶段计数、命令、源码归档及二进制哈希。
- `faults/`：默认 journal/ReadIndex 的 20 分钟真实进程活动，完整逐轮历史与结果以无损 gzip JSON Lines 保留，源码身份及故障选择保留。真实 OS 调度不可按种子精确重放。
- `acceptance/`：优化前基线、最终普通／sanitizer 回归、磁盘文件系统补充恢复测试及阶段验证日志。

从仓库根目录核对：

```bash
python3 scripts/verify-local-optimization.py benchmarks/published/local-optimization-20261021
```

该命令检查公开文件清单与 SHA-256、源码归档成员、36 轮延迟样本／百分位／计数／分桶，并重新执行每轮逐 key 有界模型检查。它不启动服务器，也不重新测量性能。文件哈希只能校验记录完整性，不能单独证明可靠性或性能结论。

复制按公开清单白名单执行，运行时节点目录、锁和数据文件未包含。所有 KV、配置应用及故障历史中的数据都是测试合成数据；不包含原有后台服务业务数据或备份。完整节点文件与失败时的运行日志在实验机器保留。

性能原始目录里的一份 `raft.state` 大小采样只表示检查点文件；journal 模式的磁盘总占用不能由它推算。写入字节／操作来自三个节点成功持久化的用户态计数，不是设备扇区写入量。P99 为各轮 P99 的中位数。

三种模式的安全要求相同。journal/read-index 在本轮均衡负载中比 journal/log 吞吐低约 7.7%，因此保留模式选择；该负向结果同样包含在完整汇总中。
