## 核验

从仓库根目录运行：

```sh
python3 scripts/verify-peer-disk.py benchmarks/published/peer-disk-20261026
python3 tests/test_peer_disk_evidence.py
sha256sum --check benchmarks/published/peer-disk-20261026/SHA256SUMS
```

`nodes/node-3/peer-main` 保存全部 576 份正式客户 gzip 样本、状态、实际参数、资源与逐值恢复哈希，`peer-smoke` 单列 96 份样本。新旧云端源码归档与逐文件清单、11 个云端准备的工具、程序哈希和编译命令一并保留。只执行当前仓库核验代码，不执行归档代码来自证。

客户 gzip 原字节保持不变；诊断里的私网地址和工作区路径映射，映射前后 SHA-256 与长度见 `control/export-map.json`。只公开原服务保护值集合的哈希。私钥、令牌、控制配置、原数据库、业务值和可执行程序均未发布。对照结束时临时节点已停止，受限控制进程留给后续独立长窗口；原服务 PID、程序及保护值保持原状。

首次 PR CI 的旧追踪测试要求两秒内产生超过 100 个 GET，实际 96 个仍应逐个核对关联。另有配置发布非零退出，但旧测试未输出客户端 stderr，因此首次日志不能确定具体失败原因。测试修正让发布使用示例原有 1500 ms 预算，保留 500 ms 健康探测，加入错误详情且不重放未知结果写入。完整普通／ASan 189 项在修正后的两组 CI 通过；首次失败、补丁、本机普通与 sanitizer 输出全部保留。
