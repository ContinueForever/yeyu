# 三台 ECS 基础手工实验的公开归档

测试源码为 `909df769ae2d9b0579a31f9d89745e589da86819`，日期为 2026-10-23。
记录由操作者通过 Workbench 运行并从三台机器导出；本文不是远程证明或重新运行实验的结果。
详细方法、结果和观测范围见[验收报告](../../../docs/cloud-acceptance-20261023.md)。

## 核验

在仓库根目录执行，只需要 Python 3 标准库，不启动节点：

```bash
python3 scripts/verify-cloud-evidence.py benchmarks/published/cloud-20261023
```

检查文件和源码快照的 SHA-256、三台一致的源码版本与二进制哈希、同一组 126 项
CTest 均通过、三台静态配置、两个 Leader 接管记录、虚拟机 boot ID 改变及服务启动、
少数派读写拒绝且提交/应用不推进、全停窗口、最终角色/进度和四个已确认值。
该检查只能核对保存记录内部的一致性，不验证操作者身份，也不重新产生故障或负载。

## 内容与证据范围

- `nodes/node-{1,2,3}/`：各自的环境、配置、二进制哈希、CTest 日志、服务日志和导出时状态。
  `ctest.log.gz` 是导出的 `ctest.log` 经 gzip 压缩，解压后保留完整测试输出。
- 节点 1 保存第一次接管、重启观察、少数派、全停检查及全停恢复的文本日志；
  节点 3 保存第二次接管；每台都有本机全停记录。
- 五项故障/恢复场景有原始文本记录。最初 `PONG / OK / ready` 的完整三条序列只有
  操作者终端截图，没有补造初始日志；后续记录中可核对 `cloud-check=ready`。
- `source.tar.gz` 是上述 Git 提交的已跟踪文件快照，排除历史
  `benchmarks/published/` 和 `benchmarks/results/`，避免重复嵌套旧证据。
  `source-manifest.json` 记录各源码文件哈希；快照没有 `.git`，完整故障测试的复现
  仍应按报告从 Git 检出该提交。
- `publication-manifest.json` 记录公开文件清单、哈希、测试提交、三份输入包哈希
  及运行二进制哈希。二进制本体、节点数据和原始压缩包不在公开归档中。

## 地址替换与保留

公开导入的日志、配置与环境文本只将三台实际私网 IPv4 替换为 `10.0.0.11`、`10.0.0.12`、`10.0.0.13`，
主机名替换为 `ecs-node-1`、`ecs-node-2`、`ecs-node-3`；替换在所有文本中保持一致。
其余文本、时间、输出、测试名称、状态数值、boot ID、Git 提交与二进制哈希均保留。
原始三份包及地址对应关系在仓库外私有保存，公开文件哈希与原始输入包哈希各自记录。
源码快照按已公开的测试提交原样保留，包括已有测试用例中的地址字面量。

这些是少量顺序请求与正常停止/重启的有限观测，没有跨机 QPS/P99、连续可用性、
云上 SIGKILL/网络分区、物理断电、多日负载或并发历史模型校验结论。
